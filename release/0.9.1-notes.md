# Release Notes - cell2cell v0.9.1

## New features

- **Searching one group of cell types against another**: `cell2cell.analysis.CorrelationObjective`
now takes `row_cells` and `col_cells`, so the reference can be a block -- one group of cell types on
the rows against another on the columns -- rather than a square matrix over one list of cells. This is
the shape of the question "how does this compartment sit relative to the rest", and only that block is
computed: the precomputed outer products and the matrix product that uses them go from `cells^2` to
`len(row_cells) * len(col_cells)`.

    - `cell2cell.core.PreparedCCIScorer` gained the same two arguments. The block it returns is the
    corresponding block of the full matrix, not an approximation of it.
    - Under `cci_type='undirected'` each entry still sums both orientations of every ligand-receptor
    pair, so restricting the rows chooses which cell-type pairs are compared, not a direction of
    signalling. Under `'directed'` the rows are senders and the columns receivers.
    - The two lists may overlap. An unordered cell pair that lands in the block twice is compared
    once when undirected, rather than being weighted double against the pairs that land once.

- **`cci_type='directed'` in the ligand-receptor search**: previously refused outright. The objective
now leaves the ligand-receptor pairs unidirectional in that mode, so A-to-B and B-to-A are scored
separately, a pool listing both directions of an interaction is accepted, and the reference is read as
senders against receivers without being made symmetric.

- **Self-interactions in the comparison**: `include_self_interactions` brings the diagonal into the
correlation, for a reference whose self-entries mean something such as a colocalization score. It is
off by default, and turning it on also stops the distances zeroing the diagonal -- otherwise every
candidate would be handed the same constant.

- **`cell2cell.preprocessing.filter_ppi_by_adata()`**: cuts a ligand-receptor list down to the genes a
dataset actually measured, which matters for a targeted panel naming a few hundred genes against a
database naming tens of thousands. The filtered partners are written to new columns beside the
originals, and a second return value reports what the filtering cost: genes on each side and whole
interactions, as totals, counts and fractions. `complex_policy='trim'`, the default, keeps the
measured subunits of a partly-measured complex, while `'strict'` drops the interaction instead; the
report counts how many surviving interactions were shortened.

## Feature updates

- **The ligand-receptor search is much faster.** The fitness of a whole population is now computed in
one call rather than one `scipy.stats.spearmanr` per candidate, which was costing more than computing
the interaction scores. Measured on 30 cell types, 700 pairs and a population of 200, a generation
went from 26.9 ms to 3.6 ms, and to 0.85 ms when combined with a block reference -- 31x. The values
are identical to the previous ones. A callable passed as `correlation` still takes the per-candidate
path, since nothing is known about it.

- `cell2cell.core.PreparedCCIScorer.distance_batch()` takes `zero_diagonal`, so the autocrine
distances can be kept when they are going to be read.

- `optimize_lr_pairs()` no longer collapses an interaction and its reverse into one candidate when the
search is directed, where the two are separate quantities.

## Fixed Bugs

- Fixed `cell2cell.plotting.tensor_factors_plot_from_loadings()` failing on a rank-1 factorization.
`axes` is reshaped to `(rank, dim)`, but the rank-1 branch indexed it as though it were flat and
handed a whole row of axes to `set_xlabel`.

- Fixed `cell2cell.external.gseapy.load_gmt()` raising `UnboundLocalError` when the file was missing
and no `backup_url` was given. It printed a message and then carried on to use a file handle that had
never been assigned; it now raises `FileNotFoundError` naming the file and the URL it tried.

## Documentation

- New tutorial, [A spatial code across several tissue sections](https://cell2cell.readthedocs.io/en/latest/tutorials/Spatial-Code-Across-Samples/),
covering single-cell resolution spatial data with several sections: building a distance or
colocalization reference, aggregating expression per cell type, searching each section and combining
the results into a consensus, and checking it on a section the search never saw. It also covers what
to do when a cell type is missing from a section, and why the reference has to be built per section
and averaged rather than by pooling coordinates from slides that each have their own origin.
